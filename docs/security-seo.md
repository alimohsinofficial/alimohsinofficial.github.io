# Search, AI content and static-site security

## Implemented in the files
Static HTML remains the canonical content and works for crawlers without WebGL. Real links connect landing summaries, detail pages, breadcrumbs and agent content. Each canonical page has a Markdown counterpart; llms.txt, llms-full.txt and the JSON manifest provide alternate representations rather than extra facts. These helper files are not a special Google ranking requirement: Google Search reads the HTML. The sitemap includes canonical HTML URLs; robots permits search and AI crawlers. No RSS remains in the active UI or metadata.

Page heads contain unique titles/descriptions, canonical URLs, robots directives, raster Open Graph/Twitter previews and JSON-LD entity graphs. Profile pages identify the author; the blog post names the author and publication date. No reviews, awards, rankings, employers or metrics have been invented. 404 is noindex; Tactical uses the Studio home canonical because its content is an alternate presentation.

The HTML meta CSP is placed before resource loads. It allows local scripts and the exact inline JSON-LD hash; script eval and inline event handlers are not allowed. Pixi's official CSP-compatible unsafe-eval bundle is loaded after Pixi and before the scenes. This filename does not mean the policy allows unsafe-eval. Styling requires unsafe-inline because GSAP and native components set style attributes. Only the optional GeoJS endpoint is allowed for external fetch; forms can post to docs.google.com. Objects, frames and base URL override are disabled. The policy intentionally does not upgrade localhost preview HTTP to HTTPS. Native contact submission is handled by Google, which owns server-side validation and abuse controls.

## Hosting limitations and deployment checks
GitHub Pages ignores _headers; meta tags cannot set HTTP-only controls such as CSP frame-ancestors, X-Frame-Options, nosniff, HSTS or Permissions-Policy. The _headers template is usable only with a compatible host/proxy. It contains appropriate values without disabling the optional device-geolocation feature. No header deployment is claimed.

Before publishing, enable/check GitHub Pages Enforce HTTPS in repository settings, confirm the correct origin, and inspect live response headers. On a compatible host apply and inspect the optional template. Do not enable mixed-content HTTP assets or publish secrets in any public file. Refresh the security.txt expiration before 14 October 2027. Dependency licenses and versions are local; track library fixes when updating them. No audit claims are made for the unfinished Blueprint library.

After publishing, verify domain ownership in Google Search Console using the owner-provided token or DNS method, submit /sitemap.xml, run URL Inspection on key pages and Google's Rich Results Test on the about/profile and article pages, and check PageSpeed Insights/Core Web Vitals. Those actions require the owner's deployment/account context; no verification token or ranking promise is fabricated here. Measure the WebGL experience on real devices before treating it as performance validated.

## Editing without a build
Maintain HTML, Tactical dossiers, the matching index.md, llms directory/collection/manifest, and sitemap together. Update dateModified/lastmod only when the underlying content actually changes. When changing inline JSON-LD, update that page's script SHA-256 value in meta CSP and the compatible-host header template; normal content/JS/CSS changes do not require a new inline-script hash. Hash the exact UTF-8 content between the JSON-LD script tags. The optional `tools/check_site.py` validator uses Python's standard library and does not generate or compile the site. Website operation never requires it.
